# Native Linux/osquery runbook — approved lab only

One-page operator runbook for S0-003 follow-up. Prerequisites: three **explicitly approved** Linux lab hosts, Node24, approved osquery package/binary, repo source, an authorized backend/PostgreSQL17 instance and per-host bearer registrations. This document grants no production access. Never install a distribution or search for tokens. Readiness here does not execute osquery or prove native acceptance.

| Step | Exact action / expected output |
|---|---|
| 1. Establish target and baseline | On each approved host: `hostname`; `uname -s`; `node --version`; `/usr/bin/osqueryi --version`. Expect unique hostname, Linux, Node24 and actual osquery version. Before collector setup record `systemctl list-unit-files --no-pager`, `ip -j address`, `ip -j route`, the approved firewall read command (`sudo nft list ruleset` where applicable), and package inventory (`dpkg-query -W` or `rpm -qa`). Keep private evidence locally; do not change rules/services. If osquery is not installed, use only the separately approved official package installation procedure; do not install unrelated dependencies. |
| 2. Validate/configure | `npm run osquery:native-check -- --binary /usr/bin/osqueryi` must show validated deb/rpm configs and NATIVE_CANDIDATE_PRESENT, with binaryExecuted=false. Then verify actual SELECTs: `/usr/bin/osqueryi --json --disable_events=true --config_path=collectors/osquery/osquery.deb.conf "SELECT name, version FROM packages"` (use rpm config on RPM host). Expect real package names/versions; failure stops setup. Copy config.example.json to a private local config, select sourceMode=osqueryi, the correct view/ecosystem, HTTPS backend endpoint and a distinct queue directory. Supply only the approved host token via OSQUERY_INGEST_TOKEN and config path via OSQUERY_COLLECTOR_CONFIG; no literal secret in history/config/report. |
| 3. Collect/deliver | `node collectors/osquery/main.mjs --once`. Expect collected/batch_delivered JSONL, accepted batch IDs and queue pending0. Backend registration must match actual `SELECT hostname, uuid FROM system_info` UUID. Do not weaken identity validation on mismatch. |
| 4. Native checklist/recovery | Capture the same package/service/address/route/firewall commands after setup and compare; only approved osquery/collector additions are allowed. Use an approved backend-side test rejection/maintenance mode to simulate a600000ms outage without changing host firewall/network; retain collector logs, restart only the collector process, restore backend, and verify all queue IDs accepted/pending0. No other service restart or configuration change. |
| 5. Verify/fresh setup | Run the exact backend SQL in followup-readiness.md for all3hosts, compare first_seen/last_seen and counts across two collections. Repeat steps1–5 on a fresh approved lab host for AC-4 (at most5hosts total), recording each step/output. Native AC evidence must identify Linux/osquery versions and filled before/after checklists, not simulator fixtures. |

Expected readiness exit2/NATIVE_NOT_AVAILABLE on the current Windows machine is correct and is **not** native execution. Candidate presence on Linux is only an executable-file check, not authenticity/permission/query success. Never relabel that as deployment PASS. All collector discovery queries stay SELECT-only; no env/cmdline/file/history queries. Full before/after host command outputs can contain sensitive details: retain them privately and redact before any upload.
